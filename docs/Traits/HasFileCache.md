# Документація по трейту HasFileCache

Трейт `HasFileCache` призначений для високоефективного кешування даних моделей у файли JSON з підтримкою багаторівневого кешування (через фасад Cache).

## Особливості трейту

*   **Оминає стандартний кеш:** Кешує вибірки безпосередньо у файли, оминаючи стандартні механізми кешування Laravel.
*   **Тегування:** Дозволяє визначати кілька наборів даних, що кешуються (тегів), кожен з яких зберігається у власний файл і може мати індивідуальні правила вибірки даних.
*   **Автоматизація:** Підтримує автоматичну локалізацію значень при генерації кешу, а також оновлення кешів при створенні, зміні та видаленні моделей.

## Проблема, яку вирішує трейт

1.  **Складні запити:** Коли для виведення даних (наприклад, меню або деревоподібних структур) потрібне виконання важких SQL-запитів з безліччю JOIN або рекурсією.
2.  **runtime overhead:** Навіть якщо запит виконується швидко, збірка об'єктів Eloquent (hydration) та їх обробка (локалізація, формування URL) займає час процесора та пам'ять.
3.  **Мережеві затримки:** При великій кількості дрібних запитів до БД або Redis у циклі (N+1) сумарна затримка мережі стає критичною.

## Коли ефективно використовувати

*   **Дані, що рідко змінюються:** Меню сайту, довідники категорій, налаштування, футери.
*   **Деревоподібні структури:** Меню каталогу, структури сторінок.
*   **Високонавантажені блоки:** Ті частини сторінки, які присутні на кожній сторінці (шапка, підвал), де затримка в 10-20мс від БД на кожному хіті перетворюється на істотне навантаження.

## Рівні кешування

*   **L1 (Файлова система):** Дані зберігаються в `storage/app/model_cache/` у вигляді готових JSON файлів для кожної мови.
*   **L2 (фасад Cache):** Якщо увімкнено прапор `use_l2_cache`, дані при першому зверненні потрапляють до Redis у десеріалізованому вигляді (Collection/Array). Це дозволяє досягти часу доступу **< 1мс**.

## Приклад використання

### 1. Підключення в моделі

Додайте трейт і визначте метод `getFileCacheDefinitions`.

```php
namespace App\Models;

use App\Traits\HasFileCache;

class MenuCatalog extends Model
{
    use HasFileCache;

    protected static function getFileCacheDefinitions(): array
    {
        return [
            'catalog_tree' => [
                'name' => 'catalog_tree', // ім'я файлу
                'query' => function () {
                    // Важливо: робіть усі важкі обчислення тут (URL, локалізація)
                    $lang = app()->getLocale();
                    $items = static::active()->defaultOrder()->get();
                    
                    // Приклад попередньої обробки
                    foreach ($items as $item) {
                        $item->url = $item->getUrl($lang);
                    }
                    
                    return $items->toTree();
                },
                'return_array' => true, // зберігати як масив (швидше при читанні)
                'use_l2_cache' => true, // увімкнути Redis
            ],
        ];
    }
}
```

### 2. Отримання даних

```php
$menu = MenuCatalog::getTaggedCache('catalog_tree');
```

Трейт автоматично:
1. Перевірить Redis.
2. Якщо в Redis порожньо, завантажить із JSON файлу.
3. Якщо файлу немає, виконає `query`, створить файл і прогріє Redis.

## Особливості та поради

### Попередня локалізація
Трейт автоматично локалізує поля, позначені як багатомовні (JSON або масиви), але для максимальної швидкості рекомендується формувати фінальні значення (наприклад, повні URL) безпосередньо всередині `query` при генерації кешу.

### Автоматична інвалідація
Трейт автоматично підписується на події `created`, `updated`, `deleted` моделі та перестворює кеш при будь-яких змінах.

### Ручне оновлення
Якщо дані залежать від інших моделей, можна викликати оновлення вручну:
```php
MenuCatalog::updateFileCache();
```

## Ефективність (бенчмарк)

| Метод | Час доступу |
| :--- | :--- |
| Прямий запит Eloquent | 50 - 200 мс |
| Читання з JSON файлу (L1) | 5 - 10 мс |
| **getTaggedCache + Redis (L2)** | **0.4 - 0.8 мс** |
